### Risk 1: Corrupted time intervals and contradictory `ExplainInput` on invalid verdicts

* **ID:** `RSK-01`
* **Category:** Correctness
* **Cause -> Event -> Consequence:** In `handleExplain()`, invalid or out-of-bounds user inputs are coerced via fallback clamping (`start >= 0 ? start : 0` and `end <= 1440 ? end : 1440`) without preserving `start < end` or rejecting non-numeric strings (`Number('abc')` becomes `NaN`, falling back to `0` and `1440`) -> When a user checks an invalid range such as `start="900"`, `end="700"` (or `start="abc"`, `end="def"`) and clicks "Explain availability", `input` becomes `{ start: 900, end: 700 }` or `{ start: 0, end: 1440 }` -> The explanation panel either displays an inverted time interval (`Room B-204 15:00–11:40`) or falsely describes a valid full-day interval (`00:00–24:00`) while stating the times are invalid (`INVALID_TIME`).
* **Affected file and line numbers:** `src/App.tsx`, lines 68–76 (and `src/explain/contract.ts`, lines 30–34, which validates `0 <= start <= 1440` and `0 <= end <= 1440` without enforcing `start < end` when `reasonCode !== 'INVALID_TIME'`).
* **Exact code line or command that would confirm it:**
```tsx
start: Number.isInteger(start) && start >= 0 ? start : 0,
end: Number.isInteger(end) && end <= 1440 ? end : 1440,

```


* **Confidence:** High
